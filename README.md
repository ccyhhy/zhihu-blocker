# 知乎批量拉黑

Chrome 扩展，按当前页面中的关键词匹配作者，或批量处理回答赞同者、粉丝和关注名单。1.2.0 增加拉黑前预览与勾选，保留排除词、白名单和可恢复任务。

## 安装与更新

1. 下载并解压，找到含 `manifest.json` 的 `zhihu-blocker` 文件夹。
2. 打开 `chrome://extensions/`，开启「开发者模式」，选择「加载已解压的扩展程序」。
3. 选择该文件夹，登录知乎并刷新已经打开的知乎页面。

更新已有扩展时，把新版文件覆盖到原来加载的文件夹，再在扩展管理页点击重新加载。保留原目录和扩展标识才能继续使用原数据；不要先删除扩展。规则与速度设置会保留。旧版拉黑记录没有账号信息，原样保留但不计入新版账号统计，也不据此跳过其他账号的用户。

## 按规则处理

- 添加「关键词 + 来源」规则，来源可选签名、评论、回答、文章。点击「预览当前页面规则匹配」，检查当前已加载内容，显示作者、关键词、来源与命中片段。
- 新安装默认关闭自动拉黑；已有明确保存的自动拉黑设置原样保留。启用「自动拉黑（跳过预览）」后，已加载内容及滚动、展开后的变化会直接进入任务。手动预览前需要关闭此设置，并结束当前运行或暂停的任务。
- 多条规则满足任意一条即可命中；不区分字母大小写，按文字包含关系匹配。
- 排除词属于对应规则：同一条发言包含排除词时跳过这条规则；同一作者另一条发言仍可命中。
- 在设置中添加白名单，填写知乎主页地址或用户标识，每行一个。所有处理方式都会跳过白名单和当前登录账号。
- 预览默认不勾选任何人，可逐人查看主页与命中片段，或选中、取消本页。只有点击「拉黑勾选的 N 人」才进入任务。
- 「查看命中内容」保留最近任务最多 5 条原文片段；执行前的依据在预览中查看。
- 关闭自动匹配，或新增、删除规则，会结束尚未完成的旧自动任务。已发出的请求会完成并保存；新规则随后重新匹配。调整白名单与速度会在后续批次生效。

规则只读取当前页面已加载且能确定直接作者的内容，不自动抓取每个用户的历史。无法识别作者或内容类型时跳过；关键词不能理解引用、讽刺或思想立场。选择具体言行用词并补充排除词，有助于减少误选，准确率仍须用你标注的案例核验。

## 预览名单并选择

- 打开某人的粉丝或关注页面，先预览该名单。
- 兼容当前的 `/people/{token}/following` 关注页面。页面明确提示关注名单不可见时，不提供处理按钮；其他权限异常由接口返回后暂停。
- 打开问题或回答页面，从弹窗选择实际加载的回答，预览其赞同者。
- 「最多检查」限制本次收集的不同用户数，范围为 1–200，包含白名单、自己及已记录用户等跳过项。首次只读取一页，点击「读取下一批候选」才继续请求，不会自动抓取全部名单。
- 名单不按关键词筛选；预览会明确显示关联来源。赞同或关注关系仅表示关联，不能单独证明一个人的素质或思想与你想排除的群体相同。
- 每页显示 20 人，本次最多保留 200 人。列表和勾选保存到本机，关闭弹窗或重启后台后可恢复。新的预览会替换上一个预览，默认重新从未勾选开始。
- 白名单、本人、该账号已记录拉黑及结果待核对用户会标注为跳过。确认时重新核对账号、规则和白名单；账号切换或规则变更会拒绝旧的规则预览，执行时仍逐批检查账号和白名单。

同一时间只有一个任务，多标签页共享。弹窗显示进度，可暂停、继续、结束；关闭弹窗不结束任务。每名成功用户立即保存独立记录和按账号统计，使用本地日期计算今日数量。

## 失败与恢复

- 登录失效、拒绝访问、接口不可用、分页结构异常或网络失败会暂停任务。检查页面后手动继续。
- 频率受限时，存在 `Retry-After` 就等到指定时间再允许继续；不会自动连续重试。
- 暂停或结束会停止后续派发，已发出的有限并发请求仍可能成功。失败数只计已尝试且明确失败的请求。
- 浏览器或后台重启后，任务暂停并保留进度。中断或无法确认结果的用户标为「待核对」，这些用户在新任务中也不会自动重发，可展开进度下方的详情进入主页，并在知乎手动核对、处理。目前不提供待核对用户的自动重新派发。
- 更换知乎账号会暂停原账号任务，切回后才可继续。记录只代表该扩展曾成功发送的操作，不能反映在网站手动解除拉黑、换设备操作或完整平台黑名单。

## 速度与性能

默认继承原版的无间隔、最多 5 个并发请求。设置拉黑间隔大于 0 时改为逐个处理。真实吞吐量取决于当前账号及接口响应，增加并发不能保证更快。任务每批确认登录账号，避免使用另一个账号继续旧任务。

手动预览只在点击时分块检查当前页面，不启用持续观察；名单每次只按需读一页，候选和任务上限为 200 人。自动模式使用一个观察器，变更合并后分块扫描。初始化和规则变更时做一次必要全量检查，平时只检查新增或变化的内容单元。规则和指纹缓存在页面中，不在页面反复读写全量历史；没有规则或关闭自动匹配时停止扫描。没有额外运行依赖、AI 服务或远程评分服务。

## 接口与已知边界

本扩展使用知乎**网页内部接口**，不是有稳定公开契约的开放平台接口：

| 用途 | 路径 |
| --- | --- |
| 确认登录账号 | GET /api/v4/me |
| 拉黑 | POST /api/v4/members/{token}/actions/block |
| 回答赞同者 | GET /api/v4/answers/{id}/upvoters |
| 粉丝、关注 | GET /api/v4/members/{token}/followers 或 /followees |

访问由扩展后台执行，使用本机登录状态。页面与弹窗不能提供任意请求地址；分页只接受同一站点、同一名单路径。

真实权限、请求验证与返回结构可能变化，不支持的响应会停止任务。2026-10-08 已在登录 Chrome 中核对回答、评论、回复、作者简介、赞同者弹窗和关注页面，补上新版评论与关注路径兼容。网页赞同者名单正常加载，但直接导航账号和赞同者 GET 均出现 `ERR_BLOCKED_BY_CLIENT`，没有取得接口返回，不能据此认定服务器接口失效，也不能确认扩展后台访问可用。测试仍使用模拟接口；真实接口权限、分页结构及拉黑验收尚未完成；1.2.0 的预览与勾选仅完成本地及隔离浏览器验证。

知乎[官方用户内容接口](https://developer.zhihu.com/docs?key=user_contents)和[官方关注接口](https://developer.zhihu.com/docs?key=user_followees)默认读本人，其他用户需 OAuth 授权，不能用于直接批量分析陌生人的全部历史。文章赞同者、评论喜爱者、完整平台黑名单同步、多回答合并名单和本地隐藏内容暂未提供。

补充核对：当前[知乎网页脚本](https://static.zhihu.com/heifetz/main.app.8bc05f70e945e7077ba2.js)使用 `answers/{id}/upvoters` 获取回答赞同者，本版已纠正原来的 `voters` 读取地址，实际账号权限和返回结构仍待验收。第三方脚本列出的两个评论点赞者地址（`comments/{id}/likers`、`innervation/comment/{id}/likers`），用户在已登录页面内对评论 `11590891560` 发起只读 GET，均返回 HTTP 404、HTML，没有用户数组、可识别用户或分页。本轮无法提供评论点赞者拉黑功能，未加入按钮；这仅确认上述候选路径在本次环境下不可用，不证明知乎所有客户端或其他接口都不存在。

## 验证

开发需要 Node.js 20 或更新版本：

```sh
npm ci --ignore-scripts
npm test
npx playwright install chromium
npm run test:browser
```

浏览器测试拦截所有页面请求，不向知乎发送真实拉黑请求。覆盖预览不触发拉黑、仅确认所选用户、勾选恢复、分页限额、账号与规则变更、白名单更新，以及作者归属、文章识别、多条发言、排除词、白名单、增量扫描、任务去重、逐项保存、暂停恢复、后台重启、账号切换、异常分页和接口失败。1000 张卡片的耗时仅是测试场景指标，不能代表实际知乎页面性能。

线上只读验收：在已登录 Chrome 中查看页面自己产生的名单请求，确认方法、目标标识、用户字段和分页游标，再核对上述 GET 的登录及权限结果。不要在只读验收阶段调用拉黑接口。实际拉黑验收应由使用者明确选择对象，并在知乎屏蔽列表核对结果。
