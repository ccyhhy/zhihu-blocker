# 知乎批量拉黑 1.3.0

Chrome 扩展，预览回答赞同者、某人的粉丝，再勾选拉黑；在用户悬浮卡片中直接屏蔽内容。根据本次需求停用关键词与自动拉黑，只保留下列入口。

| 功能 | 当前状态 |
| --- | --- |
| 回答赞同者 | 读取候选名单，预览、勾选后拉黑并本机屏蔽 |
| 评论赞同者 | 当前不可用；两个已核对的候选接口均返回 404，按钮禁用并说明原因 |
| 某人的粉丝 | 指关注这个人的账号；填写主页或在用户卡片点击「预览粉丝」 |
| 悬浮卡片屏蔽 | 提供「屏蔽并拉黑」「仅本机屏蔽」「预览粉丝」；评论和用户主页也有入口 |

回答赞同者与粉丝已完成模拟接口验证，真实账号权限、分页与拉黑结果仍待验收。没有把评论作者当作评论赞同者。

## 安装与更新

1. 解压安装包，找到含 `manifest.json` 的 `zhihu-blocker` 文件夹。
2. 打开 `chrome://extensions/`，开启「开发者模式」，点击「加载未打包的扩展程序」，选择整个文件夹。
3. 登录知乎并刷新已经打开的知乎页面。

更新已有扩展时，把新版文件复制到原来加载的文件夹，在扩展管理页点击重新加载，再刷新知乎页面。保留原目录与扩展标识，不要先删除扩展，以保留本机数据。请勿选择 `manifest.json` 文件本身。

## 预览名单与拉黑

打开回答或问题页，选择实际加载的回答，点击「预览回答赞同者」。也可直接点击回答下方的同名按钮。粉丝入口可以填写任意有效知乎用户主页，不要求当前就在粉丝页；读取的是该用户的粉丝，不是他关注的人。

首次只读取一页。默认不勾选任何人，每页显示 20 人，本次最多检查 200 名不同用户，包含本人、白名单、已记录拉黑及待核对等跳过项。需要更多候选时手动点击「读取下一批候选」。名单和勾选保存在本机，关闭、收起窗口或后台重启后可恢复；开始另一来源的预览会替换之前的预览。

检查主页并勾选后，点击「拉黑并屏蔽勾选的 N 人」。预览和勾选本身不发送拉黑请求。确认时重新检查账号与白名单，账号切换拒绝旧预览；派发时仍核对账号与白名单。成功请求会保存对应账号的拉黑记录，并加入本机屏蔽名单。

同一时间只有一个持久任务，多标签页共享。可暂停、继续、结束；关闭窗口不结束任务。暂停或结束阻止后续派发，已经发出的请求仍可能完成。

## 悬浮卡片与本机屏蔽

参考 [XIU2 的知乎增强](https://github.com/XIU2/UserScript/wiki/%E7%9F%A5%E4%B9%8E-%E5%A2%9E%E5%BC%BA)的用户卡片入口。鼠标移到用户名上，知乎的用户悬浮卡片中会出现三个按钮：

- **屏蔽并拉黑**：立即加入本机屏蔽名单，再尝试启动知乎拉黑任务。登录失效、接口错误或已有任务时，明确显示本机结果与平台任务状态；本机隐藏不代表平台拉黑成功。
- **仅本机屏蔽**：只隐藏能确定由此人直接发表的回答、文章、评论；不需要读取接口或提交平台拉黑。
- **预览粉丝**：打开这个人的粉丝候选名单，不立即拉黑。

点击页面右下角「屏蔽面板」可以打开或收起与扩展弹窗相同的窗口。在「本机屏蔽名单」或用户卡片中可恢复本机显示；**恢复显示不会解除知乎黑名单**。用户仍在待执行或已发出的拉黑请求中时，先结束任务并等待完成，再恢复显示。

按稳定的主页标识保存用户，不按昵称合并，减少同名或改名误匹配。作者不明确、悬浮卡片出现多个身份时跳过；正文引用和被回复者不作为作者。只处理已经加载的内容，不自动翻查历史。白名单会阻止拉黑和本机隐藏；本人保护使用已确认的登录账号，纯本机操作不会为此增加登录请求。

## 旧数据兼容

保留旧设置、白名单与拉黑记录。关键词规则数据仍保留，但不再执行；自动模式强制关闭，旧关键词自动任务及「关注的人」任务会结束，历史记录不删除。

此前由本扩展保存、能够确定属于当前账号的成功拉黑记录，在确认该账号后一次性加入本机屏蔽名单。恢复本机显示后不会在下次重启重新导入。更早没有账号信息的全局记录和结果待核对记录原样保留，不自动导入，也不会拿来跳过其他账号的用户。

平台上原来已经拉黑的人继续由知乎管理；插件记录不等于完整平台黑名单。本版没有同步全部平台黑名单，也不能获知在网页手动解除拉黑或换设备操作。

## 失败与性能

登录、权限、网络、分页结构或频率限制异常会暂停任务；存在 `Retry-After` 时等到指定时间再允许继续。后台重启后暂停，无法确定结果的请求标为「待核对」，在新任务中也不自动重发。更换知乎账号会暂停原账号任务，切回后才可继续。

保留原速度设置：默认无间隔、最多 5 个并发；设置间隔后逐个处理。名单逐页按需获取。一个页面观察器合并变更并分块处理，只重扫新增或发生变化的内容单元；不因插件自己的按钮插入重扫整页，不监听任务统计变化重复扫描。没有运行依赖、AI 服务或逐人历史抓取。

## 接口与边界

本扩展使用知乎网页内部接口，真实权限及返回结构可能变化，不是有稳定公开契约的开放平台接口。

| 用途 | 路径 |
| --- | --- |
| 确认登录账号 | GET /api/v4/me |
| 回答赞同者 | GET /api/v4/answers/{id}/upvoters |
| 某人的粉丝 | GET /api/v4/members/{token}/followers |
| 平台拉黑 | POST /api/v4/members/{token}/actions/block |

页面和弹窗不能提供任意请求地址；分页只接受同一知乎站点、同一名单路径。不支持的响应会停止任务。

用户在已登录页面中，对评论 `11590891560` 核对 `comments/{id}/likers` 与 `innervation/comment/{id}/likers` 两个候选路径，均返回 HTTP 404、HTML，没有用户或分页。当前无法实现评论赞同者拉黑；这仅说明上述路径在本次环境不可用，不证明所有客户端或其他接口都不存在。回答赞同者读取路径已依据当时知乎主脚本修正为 `upvoters`。
