# 知乎批量拉黑 1.4.0

Chrome 扩展。点击按钮直接批量拉黑回答赞同者或某人的粉丝，自动逐页读取并处理；没有预览、勾选或二次确认。保留用户悬浮卡片、本机内容屏蔽、白名单和可恢复任务。

| 功能 | 当前行为 |
| --- | --- |
| 回答赞同者 | 回答下方或面板选择回答，点击「拉黑回答赞同者」立即开始 |
| 某人的粉丝 | 面板填写主页，或用户卡片点击「拉黑此人的粉丝」；目标是关注这个人的账号 |
| 用户悬浮卡片 | 「屏蔽并拉黑」「仅本机屏蔽」「拉黑此人的粉丝」；评论和主页也有入口 |
| 评论赞同者 | 仍不可用；两个已核对的候选名单接口返回 404，按钮禁用 |

## 使用

面板中的人数上限留空或填写 0，表示连续处理接口允许读取到的全部名单。填写正整数时，读取到该人数后停止，跳过项也计入已读取人数。回答下方与用户悬浮卡片的快捷按钮默认不限人数。

每页通常 20 人是接口的读取批次，不是任务上限；一页处理完后自动读取下一页。移除了原来的 200 人预览上限和 2000 人任务上限。页面变化可能影响名单，实际能获取的范围取决于接口权限及分页。

保留原速度设置。新安装默认 5 并发、无额外间隔；在设置中点击「快速模式：5 并发、无间隔」可清除原来保存的拉黑间隔和页间等待，对下一批生效。自定义并发范围 1–20，间隔大于 0 时逐个处理。真实速度受接口响应和频率限制影响，没有绕过限流。

进度显示来源、读取数、成功、跳过、失败及待核对。不限人数时不显示虚假的完成百分比。可随时暂停、继续或结束，关闭和收起面板不结束任务。暂停或结束阻止后续派发，已经发出的请求仍可能完成。

## 悬浮卡片与本机屏蔽

参考 [XIU2 的知乎增强](https://github.com/XIU2/UserScript/wiki/%E7%9F%A5%E4%B9%8E-%E5%A2%9E%E5%BC%BA)的用户卡片入口，按稳定主页标识保存用户，不按昵称合并。

「屏蔽并拉黑」立即本机隐藏，再尝试启动知乎拉黑任务。接口错误、登录失效或已有任务时会分别显示本机结果与平台状态；本机隐藏不代表平台拉黑成功。「仅本机屏蔽」不读取接口，也不提交平台请求。平台成功请求同时加入本机屏蔽名单。

本机屏蔽隐藏能确定直接作者的回答、文章及评论；不把正文引用或被回复者当作者，身份不明确时跳过。点击右下角「屏蔽面板」打开同一窗口。恢复本机显示不会解除知乎黑名单；用户的待执行或已发出请求未结束时，需要结束任务并等待完成后再恢复。

## 数据兼容与保护

更新时保留原扩展目录和标识，旧白名单、速度设置和拉黑记录继续使用。旧关键词数据仍存储但不再执行，旧自动关键词与「关注的人」任务结束。旧预览数据保留但不显示、不执行；旧预览按钮消息会拒绝并提示刷新，不会被转成直接拉黑。

同一时间一个持久任务，多标签页共享。本人、白名单、当前账号的成功记录及结果待核对用户会跳过；账号与白名单在派发前重新核对。换账号会暂停旧账号任务。

能归属当前账号的旧成功记录会一次性加入本机屏蔽名单；恢复显示后不会在下一次重启重新导入。更早没有账号信息的记录和未知结果记录保留，不自动导入或用于其他账号去重。记录不等于完整平台黑名单，也不能反映网页手动解除拉黑或其他设备操作。

## 失败与性能

登录、权限、网络、返回结构和限流异常暂停任务。存在 `Retry-After` 时等到指定时间才允许继续，不自动连续重试。后台重启后保留当前页和下一页游标并暂停；无法确认结果的请求标为待核对，在其他任务中也不自动重发。

名单任务只保留当前页，处理完成才读取下一页；分页重复或游标循环会暂停。一次分页不驻留全部候选，也不新增运行依赖、AI 服务或历史内容抓取。页面使用一个增量观察器分块处理，忽略自身按钮插入。

本机屏蔽名单折叠时只更新数量，展开后分批显示；新增成功记录通过存储事件更新，不再每拉黑一人就向后台重新读取、渲染完整名单。

## 安装与更新

1. 解压安装包，找到含 `manifest.json` 的 `zhihu-blocker` 文件夹。
2. 初次安装：打开 `chrome://extensions/`，开启开发者模式，点「加载未打包的扩展程序」，选择整个文件夹，不能选择 `manifest.json` 文件。
3. 已安装旧版：把新版文件复制到原来加载的插件文件夹，再到扩展管理页点击重新加载，并刷新知乎页面。不要先移除旧扩展，以保留数据。

旧任务若已暂停，先继续或结束该任务，再启动另一个名单。

## 接口与验证范围

本扩展使用知乎网页内部接口，没有稳定公开契约；真实权限及返回结构可能变化。

| 用途 | 路径 |
| --- | --- |
| 确认登录账号 | GET /api/v4/me |
| 回答赞同者 | GET /api/v4/answers/{id}/upvoters |
| 某人的粉丝 | GET /api/v4/members/{token}/followers |
| 平台拉黑 | POST /api/v4/members/{token}/actions/block |

分页只接受同一知乎站点、同一名单路径，页面不能提供任意请求地址。用户在登录页面对评论 `11590891560` 核对 `comments/{id}/likers` 和 `innervation/comment/{id}/likers`，均为 404 HTML，没有用户或分页，因此评论赞同者仍无法实现；不改为拉黑评论作者。这仅说明已测试路径不可用。

28 项核心检查、11 项隔离浏览器检查通过。模拟 2105 人名单自动读取 106 页并完成，任务队列不超过一页；覆盖可选人数上限、跨页去重、账号和白名单变化、暂停及重启续接、循环游标、旧入口拒绝、本机屏蔽和真实作者识别。所有测试请求模拟或拦截，没有拉黑真实账号。真实接口权限、分页及平台结果仍需用户安装后验收，不能用模拟吞吐量代表知乎真实速度。
